# 0004 待办数据源与导航身份

## 背景

Agents 面板需要与待办共用左侧列表。待审/阻塞若来自瞬时标签，会随终端关闭或标签删除消失；若沿用“最新会话/同名 Agent”回退，又会跳进无关对话。审批、待审、阻塞需要跨重启保留，且只能由明确的处理记录消除。

## 决策

1. 唯一持久源仍是 `~/ai/collab/pending.md`，监督方单写。审批表保持原语义，仅追加稳定 ID、精确来源、版本；同文件增加 Agent 待办表记录待审/阻塞/执行。不新增文件或第二审批源。
2. 事项版本为递增正整数；事件带 `eventId` 与 `expectedVersion`。旧事件、错误 ID、旧版本不得清除新版本；同 ID 同版本也必比较状态，冲突不遮蔽。
3. 授权决定与执行完成分开：审批行在用户确认后结束；`类型=执行` 行只有真实操作成功（如 merge commit）才结束，失败保留。
4. 导航前核验来源会话：omp 用 session-owner lock，dsh-tui 用 session-mounts，codex/claude/opencode 用 probe；无法核验则保留事项并报原因，不回退名字。
5. 无 pane 的后台来源用 `terminal.keep` 新 tab 打开主区，不替换/关闭现有 pane；`terminal.show` 会替换 pane 视图，已否决；不用 `agent.focus` 代替对话。

## 被否决

- 用 `workbench.todo.*` 标签作唯一事项源：终端关闭/标签删除即丢，违反持久性。
- 同 ID 先到先得或账本优先：已关闭行会静默遮蔽未决记录。
- 按 `working/idle`、已读或任意回复推断待审/待用户。
- 用 latest/同名 Agent 猜来源：会跳进无关会话。

## 影响

- 监督方承担所有账本写操作与事件核验；执行者只发 `TODO-EVENT`。
- 拒绝来源不明确的旧行可显示但不可跳转。
- 现有 Agents 排序/置顶/分组/拖动/子 Agent 归属不变；图标只是状态表达。
