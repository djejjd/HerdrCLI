# 0003 多 Agent 协作规范

> **已上卷**：本规范的通用部分已提升为跨项目源文件 `~/ai/collab.md`，
> 纪律条款写入 `~/ai/rules.md` §6（A-09~A-12）。本文件保留作为项目侧历史记录，

本文件是本项目多 Agent 协作的操作层规范：把全局 §6 的交接纪律（A-01~A-08）
落到可执行的方法上。通用红线仍在 `~/ai/rules.md` §1，不在此重复。

## 1. 层级与职责

| 角色 | 是什么 | 只做什么 | 明确不做 |
|---|---|---|---|
| 裁决口 | 用户 | 不可逆操作、权限、产品取舍 | 技术裁决 |
| 监督者 | 同一时刻仅 1 个 | 拆解、派工、收件即裁、汇总、对用户单口 | 亲自实现、重复下属的调查 |
| 执行者 | N 个，按文件/模块归属 | 契约内实现与自测、交三行卡 | 越范围、自行扩任务、派工 |

换监督者必须显式交接（见 §7）。

## 2. 派工契约

派工必须一次写全六项，缺项不予受理：

```
任务ID｜目标（一句话可验收）｜可写范围（文件/目录）｜验收标准（命令+期望输出+证据类型）｜负责人｜建议模型档位
```

- 验收标准必须可执行：写「`npm test` 全绿 + 真机截图」而不是「做得好」。
- 可写范围缺失视为未定义任务，执行者可以拒接。
- 一个任务一个可检查的交付物；预计超过 2 小时先拆。
- 建议模型档位见 §10。

## 3. 交付与验收门

执行者交付三行卡：

```
证据：命令+退出码 / 截图路径 / 日志片段（注明真实机或 fixture）
剩余裁决：≤3 条，每条给选项与默认
可独立继续：有则写下一步，无则写「无」
```

监督者收件即裁，只允许三种结论：**通过 / 返修（列项 + 文件 + 负责人）/ 待用户（写明待谁待什么）**。

证据分级，跳级不验收：

1. 已送达：`send` 返回；
2. 已接单：回执含任务ID与下一步；
3. 有物证：diff、命令输出、截图、日志；
4. 通过验收：监督者复核后明确通过。

测试通过不等于验收；交互类（拖动、hover、点击）必须真机；fixture 必须标注，
不得用 fixture 冒充实拍，不得用单测冒充真机。

## 4. 并发与隔离

- **单文件单负责人**：未显式交回前，其他人不得改同一文件。
- 写代码并行建议 ≤3；有依赖、改同一文件、小活不拆。
- 新任务优先独立 worktree；脏工作区不搬动、不覆盖。
- 同一文件禁止两处同时热修：排队，或由监督者裁决谁改。

## 5. 状态机与停滞

任务：`待派 → 执行中 → 待审 → 返修 / 待用户 → 已验收 / 暂缓`。

- `working` 只表示进程在跑，不表示有进展。
- 停滞：有可做项却空闲，或结束语只说「等你验收」而没有具体裁决项。
- 执行者结束回合前必须给「剩余裁决」或「无」；约 5 分钟无交付要报证据或阻断。
- 监督者收件即裁，不把「已读」当「已处理」。
- 用有界等待代替轮询；不反复 ping、不后台互等。

## 6. 权限与副作用

- 写工作区外（如 `~/.config`）、装全局依赖、删除、发布/合并：逐项要用户批，不代批。
- 禁止 `open -a` 或以任何姿势激活前台窗口；禁止自动 focus/select；跳转只能由用户点击触发。
- 不可逆操作前先备份，回滚步骤写进交付。

## 7. 交接

交接四件套：**已改内容 / 未提交状态 / 验证结果 / 剩余风险**，并写明文件所有权转给谁。
换人须显式交回，口头「我先不动了」不算。

上下文超过约 60% 应安排收尾换人；新主题开新会话，不把多件事堆在一个会话里。

## 8. 主 Agent 额度纪律（建议阈值，触发即通报）

原则：监督者只做裁决，不做调查；翻日志、跑长测试、通读实现一律下沉给执行者。

| 动作 | 建议 | 避免 |
|---|---|---|
| 读文件 | 每轮取裁决必需的最小片段 | 通读实现、逐个看日志 |
| 看 diff | `--stat` + 关键片段 | 全量逐行读 |
| 跑测试 | 抽查一次结论级 | 每轮全量 |
| 证据 | 只要路径 + 一句结论 | 大段输出贴进对话 |

建议阈值：

- 上下文 >50% 或额度 <30%：进入只裁决模式（不调查、不开新查证）。
- 上下文 >70% 或额度 <15%：主动提出交接。
- 同一任务连续 3 轮无进展：停下问用户，不继续烧。

**触发任一阈值，必须主动通报用户**：一行说明触发的是哪条、当前档位、
建议动作（降档 / 拆任务 / 交接 / 暂停），由用户决定是否执行。

并发成本：每多一个执行者多一份消耗；写代码并行 ≤3，只读调研 ≤2，
能一个 agent 串行做完的不开第二个。

## 9. 收件账本（防遗忘）

多个审批或进展同时到达时，靠记忆必然遗漏。做法：一行一条账本，先登记再处理。

```markdown
| ID | 来源 | 类型 | 需要什么动作 | 状态 | 线程 |
|---|---|---|---|---|---|
| I-01 | ds牛马3号(t16) | 待审批 | 批部署 | 待用户 | deploy-1 |
| I-02 | ds牛马1号(t12) | 进展 | 无（归档） | 已归档 | cost-2 |
```

规则：

1. 收到即登记一句话，再决定处理顺序；
2. 处理顺序：待权限/阻塞 > 待审 > 返修 > 进展；进展类只登记、不回执；
3. 同一线程合并为一行，不新增；
4. 每轮开头先读账本，不凭上下文回忆；
5. 结束回合前对账：待用户/待审条目必须与实际状态一致；
6. 同时待审建议 ≤3 条，超出排队。

账本放 `.tmp/collab/inbox.md`（本地、gitignore），不污染仓库。

## 10. 模型档位建议

监督者按任务性质向用户建议模型档位，用户可覆盖；在任务边界换档，避免中途切换导致上下文重建。

| 档位 | 适用 |
|---|---|
| 低 | 格式化、搬运数据、单文件小改、跑命令、读文件核对 |
| 中 | 常规实现、补测试、修一般 bug、文档撰写、验收复核 |
| 高 | 架构设计、疑难定位、跨模块重构、需要判断力的裁决 |

- 监督者自身默认中档；只在复杂裁决时升档，裁决完降回。
- 高档更耗额度：额度紧张时优先降档并缩短任务，而不是硬扛。
- 建议档位写进派工契约第六项，执行者可提异议。

## 11. 记录与追溯

- 单一状态源：`docs/plans/README.md` 状态表；实施计划只维护收尾表（含负责人列）。
- 验收证据写进计划文档：路径 + 命令 + 日期；`docs/quality/` 只放本地材料，不外传。
- 决策进 ADR，规则进 rules；同主题不另开第二份文档。

## 12. 反模式

| 反模式 | 后果 | 替代 |
|---|---|---|
| 「已实现，等验收」 | 双方空转 | 三行卡 + 明确裁决项 |
| 自证完成 | 假进度 | 必须带命令输出 |
| 两人改同一文件 | 静默丢代码 | 单文件单负责人 |
| fixture 冒充实拍 | 结论失真 | 标注并真机补验 |
| 无限轮询/互等 | 烧额度不推进 | 有界等待，空闲即结束 |
| 用缩小/隐藏躲问题 | 换形式复发 | 先定根因再选方案 |
| 监督者亲自调查 | 越权且烧额度 | 派下去，只要结论 |
| 多条审批一次性通过 | 错裁漏裁 | 逐条独立裁决 |
