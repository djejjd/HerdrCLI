## 一、背景

参考 `third-party/mattpocock-skills/` 的三个技能（to-spec / to-tickets / implement-spec），结合本项目 2026-11-14 待批页改造（15 个提交、5 轮方案评审、多次返工）的经验，整理一套可落地、可检查的工单制协作方案。

本文只是方案归档；**代码与规范均未改动**。原型脚本曾放在 `.tmp/tickets/`（20 项自测通过），未进 `~/ai`，验证完成后已清理。

## 二、参考体系的内核

| 技能 | 作用 | 关键约束 |
|---|---|---|
| `to-spec` | 对话 → 规格 | 先定测试缝（seam），缝越少越好 |
| `to-tickets` | 规格 → 工单图 | 垂直切片（tracer bullet）、一张工单一个上下文窗口、每张声明 blocked by |
| `implement-spec` | 按图实现 | 一工单一 worktree + 一分支；子代理全新上下文；通信只给指针；合并者按序合；末端一次 code-review |

## 三、取舍

### 采纳

1. **工单 DAG + frontier**：并行度由依赖决定，不靠监督者凭感觉派工。
2. **指针通信**：派工只给工单号 + 规格段落 + 笔记路径，不复述需求。
3. **一工单一 worktree + 一分支**：执行隔离单位。
4. **合并者角色**：实现者不自合；一次合一个。
5. **垂直切片**：每张工单切穿所有层、单独可演示。
6. **先定测试缝**：规划阶段就回答「这条路径怎么测」。

### 不采纳

| 不采纳 | 原因 |
|---|---|
| 最大并发 | 额度、写冲突、验收带宽都不允许；保留写并发 ≤2 |
| 无审批门 | 我们发生过未报批合并（PR #3/#4/#5），必须留 A-13/A-21 |
| 自报完成 | 两次渲染崩溃（漏 import、`.child(null)`）都是自报完成放出去的 |
| 末端一次审查 | 等于用户先当测试机；改为交付前审 + 末端整体审 |
| 侧栏级 worktree 展示 | 见第五节映射 |

## 四、工单规则（草案 T-01～T-09）

- **T-01 工单必填**：id｜标题｜交付行为（用户视角）｜blocked_by｜涉及文件｜acceptance｜测试缝
- **T-02 同文件互斥**：两张未完成工单改同一文件时，**必须存在依赖路径**（A→B 或 B→A，传递闭包判定）；无路径则 lint 拒绝派工
- **T-03 只派 frontier**：阻塞已清的工单才可派；派工消息只带指针（工单号 + 规格段落 + 笔记路径）
- **T-04 隔离**：一工单 = 一 worktree + 一分支；交付前把集成分支 tip 合进自己分支
- **T-05 合并者**：合并进集成分支由固定角色执行，实现者不自合；一次一个
- **T-06 完成定义**：验收 = 证据卡（命令+退出码 / 截图 / 复跑记录）+ 独立复核（reviewer≠author）；勾选不算
- **T-07 并发上限**：`min(DAG 宽度, 3)`，写并发 ≤2；上下文 >60% 交接（沿用 A-11/A-12）
- **T-08 合并门**：集成分支 → main 前必须有 PR-Approval 账本行（PR 号 + 用户原话 + 时间 + 消息 ID），reviewer≠author，review SHA = PR head，一次只合一个（沿用 A-21）
- **T-09 用户负担**：每功能最多 1 次用户真机验收，且合并成一次（沿用 A-22）

## 五、映射：Space 是仓库，标签页才是工单

Herdr 原生「worktree 即 Space」，但 Space 在我们界面里是重量级单位（侧栏一整块、agents/终端列表都挂在下面），一工单一 Space 会让侧栏随工单膨胀。

采用映射：

| 层级 | 放什么 |
|---|---|
| **Space** | 仓库（稳定，不随工单增长） |
| **标签页** | 一个工单一张，`folder` 指向该工单 worktree |
| **agent** | 跑在对应标签的终端里，label 带工单号 |

原型已用「一工单一 Space」验证过（原生约定），改造成本约半小时（`space.py` → `tab.py`），其余逻辑不动。

## 六、冲突怎么解（三层）

1. **不让它发生**：T-02 同文件互斥 + T-07 并发上限；DAG 决定谁先谁后。
2. **早暴露**：实现者交付前把集成分支 tip 合进自己分支，冲突在最了解改动的人手里解决，并跑测试。
3. **合一次测一次**：合并者按序合，每次合并后集成分支跑测试；挂了回退这一次，不往后叠。
4. **语义冲突**（测试都绿、合起来坏）：集成分支每次合并都跑测试 + 末端双轴审查（规范/规格）。
5. **解不了的上报**：实现者不许硬合，上报带冲突文件、双方意图、测试结果；由监督者决定合并工单 / 调整顺序 / 回退。

## 七、执行闸门（保证能遵守）

原则：**写不进检查点的条款不写进规范**；查不了的降级为人工 checklist。

| 闸门 | 工具 | 不通过的后果 |
|---|---|---|
| 派工前 | `tickectl lint`（id 唯一、依赖无环、字段齐、同文件有路径） | 不派工 |
| 交付前 | `preflight.sh`（node --check、单测、check、渲染冒烟、ticket id 与 acceptance 证据） | 不交用户 |
| 合并前 | `merge-gate.sh`（PR-Approval 行、reviewer≠author、SHA 冻结、工单全闭） | 不许合 |
| 每周 | 用户负担审计（账本按任务统计指向用户的条目 ≤1） | 复盘 |

## 八、原型验证结果（2026-11-14，独立 agent）

产物：8 个模块（每个 ≤150 行，最长函数 36 行；20 项自测通过），验证后已清理。

结论：**可采纳**。

- `lint / next / open / close` 四命令跑通；真实建 worktree + 标签页/Space + 分支，侧栏可识别
- worktree 根改到 `<repo>/.tmp/worktrees/<id>` 后**不再需要全局写权限**（原 `~/.herdr/worktrees` 每次建/删都要审批）
- 修掉两个设计问题：同文件依赖改为「存在依赖路径」；合并门要求「有提交 + 可达」而非仅 ancestry（空分支曾误判已合并）
- 加文件锁与幂等恢复（重复 open、state 丢失接管/收尾）

已知缺口与风险：

1. 当前布局的自定义侧栏不按仓库嵌套 worktree（原生 `spaces` mod 有，但布局未使用）；采用标签页映射后此项消失
2. `herdr-app ls` 的 `recent` 会残留一条已删 Space 名
3. 默认 `.tmp/worktrees` 要求仓库忽略 `.tmp/`
4. 合并门是本地 ancestry 检查，不是 PR 评审门；特殊仓库需 `--target`
5. 锁是 state 文件粒度，不是仓库粒度
6. `space.new` 失败回滚是 best-effort，极端情况可能留孤儿 Space
7. 未处理 submodule / LFS / 远程 machine
